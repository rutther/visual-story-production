# 持续记录与方法更新

> 阶段规则：本章中的编码、MP4、成片检查均以当前交付范围和用户授权为前提。Web预览阶段不要求生成视频；先完成可编辑工程的实际检查。历史案例中的数量、参数和角色不是新项目默认值。

## 1. 记录的三个层次

项目日志：具体内容、文件、版本、时间、画面和修改。用于继续当前工作。

方法条目：问题类别、适用条件、处理步骤、失败边界和验证。用于不同项目复用。

工具/skill入口：把方法组织为可执行工作流，指向必要资源，按当前环境发现工具。入口不应该复制整段项目历史。

## 2. 边做边记的时机

- 完成内容理解：保存目标、改稿范围、叙事结构和视觉任务。
- 审阅一批素材：立即保存实际观察，避免以后重复从头查看。
- 采用参考：保存出处、借鉴点和不适用处。
- 写实现：保存坐标、时间模型、依赖和关键参数理由。
- 发现问题：先记录状态和证据，再改代码。
- 修正后：同位置复查，把“待复查”改为有依据的结果。
- 交付前：绑定当前产物版本，列明剩余限制。

不需要每次操作写一篇散文；记录真正改变下一步行动的判断、观察、错误和解决方案。

## 3. 从项目案例归纳方法

按以下结构写一条：

```
问题类别：
触发条件：
如何识别：
原因与替代解释：
处理步骤：
技术要点：
如何验证：
不适用/失败边界：
实例及证据：
```

例如：某会议照片两侧人物被裁掉，是“多主体宽幅素材的裁切”问题。通用方法是先辨认关系主体并选择能保留它们的窗口；不是“所有照片必须使用某个宽高比”。

例如：小岛缺失，是“底图精度与目标尺度不匹配”问题。通用方法是先核对数据是否包含目标、再选择精度；不是“任何地图都必须下载最高精度”。

例如：时间线遗漏年月，是“输入时间表达覆盖不完整”问题。通用方法是覆盖完整日期、年月、年份和相对时间并检查；不是为下一项目固定一组历史节点。

## 4. 避免错误总结

- 一次好看的参数不自动成为普遍最佳值。
- 代码退出0不是方法有效的证据。
- 一个AI的自评分不是人类偏好数据。
- 某用户的选择属于该用户/用途，不能当全部观众的喜好。
- 时间节省必须同时说明质量和范围是否保持。
- 新工具解决了一个问题，也可能带来缓存、字体、导出和依赖的新问题。

## 5. 方法的状态

使用`候选、已在历史制作案例验证、跨项目验证、废弃/有例外`等状态。每次验证写任务类型、设备、内容密度、工具和实际结果。无法验证的假设保留为假设。

不要伪造A/B测试、真人评价、审美评分或性能对比。想比较两个方案，用同一真实内容、同一规格和明确比较点，而非同时改变所有变量。

## 6. 为其他会话和AI准备交接

交接须包含：

1. 当前目标及所有仍有效的用户修正。
2. 项目参数和源材料位置。
3. 哪些工作已完成，证据在哪，哪些观察可复用。
4. 当前活跃进程/作业及最后一次确认状态。
5. 已知问题、未验证项和下一项具体行动。
6. 不能再次运行的覆盖式脚本、废弃产物和缓存风险。

下一代理先读当前状态再检查实际文件和进程，不把摘要当完成证明，不重新启动仍运行的渲染。

## 7. 更新skill的边界

更新通用skill时只加可迁移规则和必要脚本；项目内容留在案例/配置。采用用户直接授权的修改范围，不把技能中的菜单、固定访谈和审批流程叠到已有明确任务上。

工具名称、路径、浏览器能力和依赖从当前harness发现。缺少能力时记录替代步骤及验证范围，不宣称使用不存在的工具。

每次方法更新保存版本、变化、原因和来源；旧方法不适用时写出边界，避免新会话继续机械套用。
