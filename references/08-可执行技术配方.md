# 可执行技术配方

> 阶段规则：本章中的编码、MP4、成片检查均以当前交付范围和用户授权为前提。Web预览阶段不要求生成视频；先完成可编辑工程的实际检查。历史案例中的数量、参数和角色不是新项目默认值。

以下是与编辑工具无关的计算与数据方法。实现前按当前工具、画幅和语言转换接口；示例不是当前项目已经通过的测试。

## 配方A：确定性时间状态

先分开全局时间和镜头内部时间：

```js
const clamp01 = x => Math.max(0, Math.min(1, x));
const easeOut = x => 1 - Math.pow(1 - clamp01(x), 3);
const localTime = globalTime - shot.start;
const progress = easeOut((localTime - event.start) / event.duration);
const position = from + (to - from) * progress;
```

`event.start`来自讲述的意义时刻，不必从镜头0秒开始。`event.duration`是运动时间，不是整段时间。完成后保持`to`，不靠动画结束回调才能正确到位。

检查：从头播放、直接定位中间、直接定位末段，再定位回来，状态应一致。依赖随机、墙钟或上次播放的累计状态会破坏这种一致性。

播放器的秒时间与实际展示帧还要分开。某事件在两帧之间发生，章节定位要落到事件后的第一帧；恰好落在帧边界时，媒体时间精度舍入可能显示前一帧。可以从实际帧率求起始帧，再加远小于一帧的正偏移，并实际检查定位后画面：

```js
const firstFrame = Math.ceil(eventTime * fps);
const seekTime = firstFrame / fps + epsilon; // 0 < epsilon << 1/fps
```

这是播放定位方法，不是删剪语音的依据。不要用它截掉开头音节。`currentTime`赋值成功、时间数字改变和新画面实际出现是不同证据；等待媒体定位后再看图。控件尽量放在成片区域外，防止暂停时遮住影片自己的字幕和全局信息。

## 配方B：词边界到视觉事件

```text
1. 选择本段中要触发变化的完整词组。
2. 按出现次序确定字符位置，保存 occurrence 或明确字符范围。
3. 将词边界文本从左到右与正文匹配，游标只向后。
4. 找到覆盖目标字符范围的时间。
5. 设 event.start；需要提前展示主体时，单独设主体出现时间。
6. 合成/剪辑之后重新核对实际音频，不沿用旧语速下的时间。
```

异常：转录规范化了数字、文本同义改写、词边界缺失、重复词定位错位或源编码错误。匹配失败必须可见于检查记录。备用比例时间可用于制作，但关键事件需要实际复查。

字幕保存`text/start/end/sourceRange`，便于追溯完整文本。不要只保存渲染后的HTML字符串。

## 配方C：照片裁切与标注共用变换

设源图像中的裁切区域为`(cx, cy, cw, ch)`，窗口为`(W, H)`。若采用覆盖窗口：

```text
scale = max(W / cw, H / ch)
imageLeft = (W - scale * cw) / 2 - scale * cx
imageTop  = (H - scale * ch) / 2 - scale * cy
```

源图中的点`(px, py)`转换为：

```text
screenX = imageLeft + scale * px
screenY = imageTop  + scale * py
```

源矩形标注同样转换。把图片和标注放进同一个变换容器，可以减少各自手算导致的错位。先验证最终裁切，再插值进入状态；不能只看终点框对了，就假定运动中也对。

原图长宽比、EXIF方向和实际解码方向先确认。需要保留全图时使用适配窗口而非覆盖，并把留白作为明确版式。

## 配方D：地图中的世界长度与屏幕长度

```text
screenScale = min(windowWidth / viewBoxWidth,
                  windowHeight / viewBoxHeight)
worldFontSize = desiredScreenFontSize / screenScale
worldMarkerRadius = desiredScreenRadius / screenScale
worldOffset = desiredScreenOffset / screenScale
```

有投影转换时，地点先从经纬度转世界坐标，再从世界坐标转屏幕。不要把这两个步骤混成布局像素。

标签避让：

1. 对每个标签计算当前字体的实际/估算包围盒。
2. 优先放目标和关键比较点，再放背景名称。
3. 检查窗口边界、字幕区域和已接受的标签。
4. 尝试左右、上下位置；必要时隐藏低优先级标签。
5. 检查几个缩放中间状态，防止标签跳动和瞬间挤压。

近似字宽只用于定位候选；复杂文字、字距、RTL语言和字体回退应使用实际文本测量。

## 配方E：连续状态与连线

主体在两方之间迁移时，连线端点应从主体当前位置求出：

```text
subjectX = fromX + (toX - fromX) * progress
lineEnd = (subjectX, subjectY)
```

旧线退出与新线建立是两个状态，可在同一时间窗口交接。使用dash绘线时，长度必须覆盖整条路径；短dash周期可能在“完全隐藏”状态仍漏出尾段。检查0%、50%、100%三态，并核对端点与节点边缘。

## 配方F：中文与关键串的安全渲染

先按文本拆字幕，再对需要保持完整的数字、型号和拉丁串创建独立文本节点/元素。优先使用DOM文本节点或组件渲染；不要在已经HTML转义的字符串上做正则拼HTML，以免把`&amp;`等实体破坏。

检查行首结束标点、缩写拆行、日期/数值与单位、最大长度和实际字体。语言不同要重新判断规则，不能把中文策略直接用于阿拉伯文或日文。

## 配方G：逐帧缓存而不降低帧率

每一帧先计算完整状态。处于移动、遮罩、渐变或其他实际变化窗口时，帧键含当前帧；稳定状态则可用内容、对象位置、字幕、标签、进度和覆盖层组成离散键。

相同键可以重复写入同一图像，但输出仍有每一帧。检查：

- 缓存键是否遗漏未来的定时事件？
- 当前进度、日期或高亮是否仍连续/按设计更新？
- 字体或图片加载变化是否使旧帧不再有效？
- 文件总帧数是否准确，音画是否同长？

不要靠“镜头超过4秒就一定静态”这样的假设处理所有布局；不同事件有不同窗口。优化必须覆盖实际动画模型。

启动长片渲染前，先用包含大地图、照片推拉、密集文字和标识的代表区间测耗时。分别记录首次加载与素材预热后的耗时、实际生成的不同图像数、输出帧数和编码时间。输出帧率不等于生成速度；一帧可以复用多次，复杂地图又可能在每帧都重新栅格化。不能用一个静止标题页的速度估算全片。

分清瓶颈：素材读取、字体就绪、DOM复制/序列化、图像解码/栅格化、PNG压缩、传输和视频编码。内联图片可以减少网络请求，但仍会重复图像解码与栅格化。先测量再选择缓存或预渲染层；任何优化都要比较同一时间点的实际画面和语义事件。稳定帧的缓存键不应因无关的墙钟变化而刷新，真实进度变化则必须保留。

测速还要防止测到浏览器的已有位图缓存：多次解码完全相同的SVG地址，可能跳过首轮实际工作。分别报告首轮、相同输入复用、不同输入三种数据；测试变化画面时保持生产素材密度，并明确是否包含传输和编码。小样很快而整片很慢，说明证据尚未覆盖整条流水线；不能因此宣布根因已找到或盲目替换API。后续应在完整流水线记录每个阶段的时间，检查队列、运行环境和调度差异。

## 配方H：可恢复的长任务

保存：产物版本、依赖hash、完整时间线、已完成区间、当前进程handle、最后确认时间、输出文件状态和下一步。

观察超时：先检查同一handle和实际输出是否增长。

进程终止：明确停止原因，检查已完成片段是否可复用，再选择恢复或重启。

源内容变化：比较依赖与区间；不能仅凭文件存在就沿用旧片段。无关文档更新不应使像素缓存失效，但影响画面的代码和素材必须入依赖。

可以让一个独立检查任务等待当前编码器的完成信号，再检查依赖hash、完整解码、时长和帧数，保存与新文件hash关联的结果。这个检查任务不能另起一个编码器，也不能在旧成片仍存在时，仅凭文件存在就开始验收。技术通过后仍保留画面、声音和播放器的实际复查步骤。

渲染输入PNG、完成的编码视频和浏览器播放画面是三个不同阶段。输入图可提前检查布局，但不能证明编码与播放正确。抽样稀疏时，多个目标时间可能落到同一张样本；记录实际帧号和时间，不把重复样本当作多个动画阶段已经检查。

## 中性场景数据示例

```json
{
  "id": "shot_001",
  "sourceTextRange": [0, 120],
  "voiceAssetId": "voice_001",
  "timeline": {"startFrame": 0, "frames": 240},
  "informationTask": "relationship-change",
  "sources": [{"assetId": "asset_001", "purpose": "context"}],
  "layout": "selected-project-layout",
  "events": [{"semanticCue": "target phrase", "localStart": 3.2, "duration": 0.8}],
  "captions": [{"text": "Actual caption", "start": 0, "end": 2.1}],
  "review": {"state": "pending", "evidence": []}
}
```

240帧等数值只是结构示例。工程必须自行填写实际内容和规格。模板不能当作已有材料、已审阅或已验收的证据。
