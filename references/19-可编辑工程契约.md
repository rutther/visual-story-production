# 可编辑工程：把内容与表现分开

## 四份独立输入

1. 原始正文与声音，保留字节版本；显示标题不进入旁白。
2. 素材索引，保存身份、用途、裁切、来源和派生关系。
3. 视觉单位与cue，保存原文字符范围、实际音频时间和信息任务。
4. 主题与构图参数，保存画幅、字体、字号层级、色彩角色和安全区。

一个主题常量改变，不应重写正文；修改一句口播则要重新确认音频、字幕、cue和后续时间。所有前后依赖列入受影响范围。

## 建议组件接口

```text
mount(container, scene, assets) -> component
prepare() -> readiness including errors
seek(localSeconds, motionPolicy) -> full state at t
dispose() -> remove listeners, timeline and GPU resources
snapshot() -> optional representation only when authorized/needed
```

接口是契约，可按具体库适配。mount不应依赖上一个镜头的残留；prepare等待字体、图片和地图，失败可诊断；seek从数据计算完整状态，而非累计执行“下一步”。dispose防止多条时间轴继续跑。预览等待资源和播放时钟要区分，慢加载不能让旁白已经说完而图仍未出现。

## 单一时钟与语义节点

使用音频时间或编辑器主时间，sceneLocal = global - sceneStart。把每个cue写明源词、出现序号/字符范围、开始、动作长度、稳定阅读长度。中文重复短语不能总匹配第一处。

`scripts/motion_math.py`提供小型纯函数：时间进度、覆盖裁切变换、源坐标到画面坐标、累计帧边界。它不替代成熟动画库，不提供物理模型或渲染器。零持续时间是瞬时切换，负持续时间是输入错误。

顺序镜头在边界切换；叠化用明确的独立转场窗口，不能把重叠误报为漏洞。包内project检查器使用不重叠叙事单位，复合镜头图层在该单位内部建模；复杂编辑器工程需适配自身时间模型。

## GIS与屏幕层同步

世界坐标保留经纬度/高程。相机按主时间计算center/zoom/pitch/bearing，标签每帧投影到屏幕。地理定位外层与装饰入场内层分开，避免缓动覆盖坐标。少量重要标签优先避让，背景标签可按尺度隐藏。

完整地图准备要包含数据/瓦片/字体和渲染帧就绪。配置区域、数据精度和缓存覆盖；不能在地图尚未绘制时截空白帧。脱网资源需合法保存，动态服务条款不允许缓存时不能假装支持离线。

## Web预览与输出阶段

预览先交互：暂停、拖动、重复定位、从其他场景回来、改变窗口尺寸后重查。只有用户要求后才接编码流程。即使有编码功能，也不得默认每改一段就渲染MP4。

后续输出时使用同一场景函数并锁定依赖；WebGL、Canvas、HTML/SVG各有快照边界。图片与SVG image、字体、CSS、地图资源全部计入，不能只扫描一个目录。

## 交接文件

README包含实际启动方法；STATE记录最新目标和下一动作；scene数据负责镜头；reference卡负责借鉴来源；evidence负责已观察范围；DECISIONS记录为什么这样处理。项目包与公开方法包分开，后者不带客户资产或本地绝对路径。

官方技术入口（2026-10-18核对页面，具体版本仍须在项目锁定）：[GSAP Timeline](https://gsap.com/docs/v3/GSAP/Timeline/)、[MapLibre terrain example](https://maplibre.org/maplibre-gl-js/docs/examples/3d-terrain/)、[Remotion deterministic rendering guidance](https://www.remotion.dev/docs/flickering)。这些支持工具选择，不代表该技能在所有栈中已实测。
