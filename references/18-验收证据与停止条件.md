# 验收应证明作品，而不是证明检查记录存在

## 状态分开

`planned → storyboard → implemented → observed → accepted` 是不同状态。工程可运行不等于观察过，代理观察过不等于用户接受。每个问题单独关闭，整片完成需覆盖全部有效需求。

记录必须包含版本、观察范围、方法、证据和发现。`normalSpeed=true`、`storyboardMatch=true`等自填布尔值只是声明；若没有相应观察来源，不能据此判定通过。

## 证据强度

| 记录 | 可以支持 | 不可以支持 |
|---|---|---|
| 原文件hash与文本范围 | 指定版本、字面一致 | 意义正确、声音发音 |
| DOM、边界与加载检查 | 结构、几何候选 | 实际可见、审美成立 |
| 对应时点实际截图 | 该帧裁切、标签和层级 | 中间运动、声音、全片 |
| 连续动态观察 | 所观察区间的运动和切点 | 区间外质量、未听声音 |
| 播放器时间推进/ended | 播放机制能推进/结束 | 观察者看完或听完 |
| 自动转录与技术音频指标 | 内容差异候选、静音、电平 | 全部读音、主观听感 |
| 用户明确反馈 | 对应范围接受或否定 | 未展示范围的接受 |

截图以非零间隔采样，只是“正常速度播放期间的采样”，不能改名成“完整连续目视验收”。工具只能提供离散图片时，将中间运动观感保留未验证；可增加样本定位错误，但不能通过增加样本数量伪造能力。

## 需求到证据

每项有效需求列：需要什么证据、当前证据是否覆盖、未覆盖的具体条件。用户要求完整影片时，代表片段不足；用户只要可编辑Web时，不能凭空增加MP4作为硬门槛。

当前授权阶段决定检查范围：

- 研究：可核对来源、实际观察与可迁移结论。
- 分镜：同一场景首中尾图、语句映射、空间与身份连续。
- Web/编辑工程：实际运行、素材加载、中文、时间控制、进出场与正常速度观察。
- 导出：只有已进入此阶段才检查编码、声音合入、版本对应和最终文件。
- 发布：用户明确授权后，再处理账号与对外动作。

没有明确要求每一步等用户批准。内部制作阶段可以自主前进；用户明确设定的“验收后导出”必须保留。

## 故障定位而非凑检查数量

画面无变化：先核对实际入口与资源版本。内容存在但不见：检查祖先透明度、overflow、mask、clip-path与画面像素。正反定位不同：先定位差异区域，再区分状态残留、字体、纹理采样或加载时序。仅有哈希不同不能证明骨架不同。

实质性修复后复查原问题时点和相邻边界。其他未改部分可以继承证据，但须说明依赖未变；影响字体、字幕切分、共用引擎时扩大检查。

## 结束与交付

所有当前交付要求都已处理、已知缺陷关闭、证据覆盖相应范围后，交付可用文件与真实限制。外部条件阻塞时先完成独立工作，提供具体缺口和最少输入。用户认可不需要自动替整个系统增加虚假的测试通过标记。

维护方法包也适用同一原则：结构验证、迁移解压测试和示例试用可以验证包的可用性；无法证明所有模型都具有相同能力。不得声称跨harness效果一致已实测。
