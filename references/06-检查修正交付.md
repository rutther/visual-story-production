# 检查、修正与交付

> 阶段规则：本章中的编码、MP4、成片检查均以当前交付范围和用户授权为前提。Web预览阶段不要求生成视频；先完成可编辑工程的实际检查。历史案例中的数量、参数和角色不是新项目默认值。

## 1. 验收分层

| 层级 | 能证明什么 | 不能证明什么 |
|---|---|---|
| 原材料审阅 | 实际看过的内容、可用区间、主体 | 全片使用正确、最终质量 |
| 数据/代码检查 | 文件、时间、边界、参数和约束 | 画面好看、动作有意义 |
| 静帧检查 | 排版、裁切、单位、字幕、相应状态 | 转场顺滑、节奏、声音 |
| 连续动态检查 | 动作、切点、阅读停留、闪烁与流程 | 未听取的声音正确 |
| 听音/转录 | 相应范围的内容、读音、混音 | 视频画面合适 |
| 最终编码检查 | 当前输出实际参数、解码、编码后画面 | 用户审美接受、所有工具未检查的能力 |

证据与当前文件hash/版本绑定；旧版本的检查不能整份继承。未改区间的有效观察可以复用，记录继承条件。

## 2. 检查顺序

先检查委托目标和内容是否完整，再检查素材对应、画面和声音，最后处理细节。已知的内容错误、漏素材、字幕遮挡、声音削波和播放失败优先于美化。

全部镜头至少检查进入、主要状态和末段；复杂动作与切点增加采样。抽样范围必须记录。用户要求连续观看时按要求执行；工具没有该能力则说明缺口，并完成能检查的部分。

## 3. 静帧检查清单

- 标题、字幕、单位、日期与人名是否准确？
- 文字是否溢出、遮挡、被裁切或缺字？
- 图片主体、重要动作和关键铭牌是否保留？
- 地图地点、标签和底图精度是否正确？
- 图表轴、尺度、分母、数量和图例是否清楚？
- 不同镜头是否提供新信息，而非重复同图或同骨架？
- 全局信息是否对节目有用，是否混入内部制作说明？

## 4. 动态检查清单

- 焦点是否跟随讲述，关键结果是否在合适时刻出现？
- 进出场是否产生跳变、残影、短暂黑帧或异步空图？
- 文本是否有足够读完时间，动画是否让人等太久？
- 主体移动和连线端点是否同步？
- 用户拖动、从头播放、暂停、恢复是否得到正确状态？
- 确定性定位是否与连续播放、导出一致？

## 5. 诊断与修正记录

每个问题写：

`版本 → 时间/状态 → 实际观察 → 影响 → 原因假设 → 修改 → 相同位置复查 → 相邻区间复查 → 结论/仍未验证`

不要用“反思”“以后注意”代替修正。批量处理同原因的问题，但每种独立原因要有自己的验证。连续微调没有改善时保留较好版本，重新检查骨架、内容匹配或工具路径。

## 6. 自动检查的正确用法

范围、重叠、黑帧、静止、字宽、峰值等检测定位候选问题。预期的照片停留不是卡顿；故意暗场不是自动错误；入场移动超出内容区可能是有意动画。代理需结合实际图和任务判断。

检测通过不能证明审美和语义；误报也不能成为忽略所有检测的理由。记录误报条件，让下一次检查更有针对性。

## 7. 交付

交付当前成片或可用页面、可续改工程、必要资源、启动/导出说明、入选素材与时间线、实际检查记录和方法增量。链接和路径应可用；媒体预览本地文件需使用实际绝对路径。

说明简短、真实。清楚区分已完成、已观察、未验证和缺口。不要把粗剪、代表页、仅生成文件或技术通过称为整项完成。

## 8. 完成与停滞

完成前逐项对原需求找证据：没有遗漏才可结束目标。预算接近、文件存在、绿色日志、或没有发现明显问题都不是单独的完成条件。

等待要绑定当前仍存活的进程/作业。观察超时不表示作业终止；检查原handle再决定。确实缺少外部输入时先完成不依赖它的工作，再说明最少缺口，不制造完成状态。

## 裁切后的内容存在性

DOM里有文本、文字范围有宽高，不等于观众能看到。clip-path: inset(0px 100% 0px 0px)会把文字全部裁掉，但Range的边界仍存在。检查祖先的display、visibility、opacity之外，还要检查裁切；百分数与0px可能混用，不能要求每一侧都是百分数才判断。实际像素、原生画面和自动候选仍需相互校验，不能把候选为零当成审美或信息覆盖通过。

最终编码采样发现介绍段长时间无主体内容时，沿用提供的文字和词边界，补充人物身份、角色、状态、地点或机制。不能为了“非空”提前十秒把后面的话一次性全放出来，也不能只堆装饰图标。先处理一个明确镜头，再复查和进入下一个。

修改前从实际入口HTML核对加载脚本。工程里名称相似的旧author.js、subtitle变体和导出脚本可能共存；改到不加载的旧文件，命令成功也不会改变画面。用原生页面是否出现新组件作为直接证据，发现无变化时检查入口与网络资源，而非盲目重复改样式。

完整裁切判断还需展开CSS四边缩写：一个值作用四边，两个值分别作用纵横，三个值分别为上、横、下，四个值为上右下左；同时判断横向和纵向总裁切。圆角参数不属于裁切距离。这里只能判断完全消失；部分裁切、蒙版、溢出和低对比度仍需结合实际像素与画面检查。

交付编码视频时，把四种证据串起来：锁定的源版本、实际编码作业、当前成片hash和查看记录必须一致。只交付可编辑工程时，核对源版本、资源和实际预览记录即可，不为打包而编码。工程包CRC与逐文件hash只能证明归档完整，再从独立目录解压、启动并操作定位和播放，才能发现遗漏共享脚本、相对路径、字体或服务端口的实际问题。解压测试保留原工程，不能通过覆盖正在工作的目录来验证迁移。
